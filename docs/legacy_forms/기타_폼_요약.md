### 부적합 처리 규칙 (`DefectRepository`)
- 처리구분(`reworkstep`): **출하 / 재처리 / 선별 / 보류** (콤보 하드코딩)
- 판정 저장 = `check_complete = 1` (결정완료). 검사번호 단위 일괄 저장 시에는 처리구분이 **재처리·출하일 때만** 결정완료
- 재처리 대기 = `reworkstep = '재처리' AND plan_complete = 0` → 스케줄 화면에서 재처리 배정 시 `plan_complete = 1`
- 완료 = 완료자·완료일·재작업 메모

| # | 신규 반영 |
|-|-|
| D1 | `defect_occurrence.decision` 값에 **선별(SORT)·보류(HOLD)** 추가, 구 "출하" = `CONDITIONAL_ACCEPT` 또는 `SHIP` 코드로 정리 (공통코드 `DEFECT_ACTION` 반영됨) |
| D2 | 상태: 미결정(OPEN) → 결정(DECIDED) → 재작업 배정(REWORKING) → 완료(COMPLETED) — 구 `check_complete`·`plan_complete` 대응 |
| D3 | 판정자·완료자는 문자열 이름 → 신규는 `*_employee_id` |

### 권한·설정 규칙
- 로그인 없음. **PC 설정 파일의 부서**(`DBHelper.GetDepartment`)로 상단 메뉴 표시 여부 결정
- 부서가 비어 있거나 `t_dept`에 없으면 **모든 메뉴 표시** (fail-open)
- 옵션 화면 진입 비밀번호가 **코드 상수** (`F_Option.cs` 24행 `OPTION_PASSWORD`)
- 설정 키: `InspectionTemplateFolder`, `PartDrawingFolder`, `PartImageFolder` (경로)

| # | 신규 반영 |
|-|-|
| M1 | 로그인 계정(`app_user`) + 역할(`role`) 기반. 권한 없는 메뉴·API는 **기본 차단**(fail-closed) |
| M2 | 구 부서 → 역할 1:1 생성, `t_dept_menu` → `role_menu` 이관 (메뉴 키 = 구 메뉴 텍스트 → 신규 menu_key 매핑표 필요) |
| M3 | 단말(PC)별 부서 고정 개념은 `workstation`에 기본 역할/부서 컬럼으로 필요한지 확인 |
| M4 | 옵션 비밀번호 상수 제거 → 관리자 역할 권한으로 대체. 경로 설정 3종은 DB 첨부 보관으로 불필요 |
